# Java 后端 30 天学习清单：以若依完成一个业务模块

建立日期：2026-10-20。状态：计划，全部待验收。

主线：JDK 17 + 上传的 RuoYi-Vue springboot3。对照：Java 8 + 上传的 springboot2。FBA / FBA-Slim 保留为分层职责的辅助类比。

## 1. 一个月后的具体目标

目标是在已有若依系统内，能够开始接手边界清楚的业务开发：读懂接口、修改 SQL、实现简单业务模块、联调、定位常见错误，并提交可审查的代码。项目登录、用户、角色等基础能力复用若依；不要求一个月内自行搭建整套后台框架。

完成标准：给出一个普通业务需求，能说清表结构、接口、业务规则和权限，完成实现并提供验证证据。允许查官方文档、参考若依源码和使用 AI，但必须能解释改动、独立定位错误，并完成一次需求变更。

这份计划由本次学习目标设计，不是若依官方课程。能否接手公司某项具体任务，仍需对照该任务的复杂度和验收结果，不能把“学完清单”等同于已经能承担固定比例的后端工作。

时间预算暂按每周约 18 小时：普通学习日约 2 小时，两个集中实践日各约 4 小时。四周约 72 小时，最后两天约 4 小时。这里的第 6、7 日等表示集中实践日，可移到自己的周末，不强行对应日历星期。

## 3. 本月贯穿项目：巡检工单

这是新增教学练习，不是声称若依内置了这一业务，也不使用公司敏感数据。

主表 inspection_work_order：工单编号、标题、描述、填报人、状态、创建时间、更新时间；截止日期在最后一周作为变更需求补充。

记录表 inspection_work_order_log：工单 ID、操作类型、操作人、操作时间、处理意见、操作前后状态。复用现有用户表，不重新开发用户、角色和登录。

| 规则 | 本月实现范围 |
| --- | --- |
| 状态 | 草稿 → 已提交 → 已通过 / 已驳回；驳回后可编辑并重新提交 |
| 编辑与删除 | 填报人只能编辑自己的草稿或驳回工单；仅草稿可删除 |
| 可见范围 | 填报人查看自己的工单；审核人查看和审核已提交及已处理工单 |
| 审核 | 仅具备审核权限的用户可处理已提交工单 |
| 身份字段 | 填报人、操作人等由服务端当前登录信息确定；客户端不能任意指定 |
| 记录 | 提交、审核等状态变化与记录写入处于同一数据库事务 |
| 重复请求 | 连续或并发审核同一张已提交工单，最多成功一次，只新增一条成功审核记录 |
| 查询 | 按标题、状态、创建时间筛选，分页，详情包含操作记录 |

练习权限规则是为控制学习范围作出的选择，不代表公司的真实权限要求。最终回归需覆盖列表、详情、修改、删除、提交、审核、记录查询；如果做导出，导出也必须遵循同一可见范围。

## 4. 先建立的架构认识

开始写代码前先弄清：请求进入后如何经过认证与权限处理，到 Controller、Service、Mapper、数据库，再返回响应。实际请求不一定经过每一项校验，阅读时以所追踪接口为准。

| 部分 | 负责什么 | 需要能回答的问题 |
| --- | --- | --- |
| Controller | 接收请求、绑定和校验参数、调用业务、组织响应 | URL 对应哪个方法？参数从哪里来？ |
| Service | 判断业务规则，协调多个数据操作，确定事务边界 | 谁能改、何时能改？失败时应撤销什么？ |
| Mapper + XML | 执行 SQL，把结果映射成 Java 对象 | 参数如何绑定？查询和更新影响哪些行？ |
| MySQL | 持久化数据，约束、事务与索引 | 怎样防止重复和部分写入？ |
| Spring | 创建和连接项目组件，提供 MVC、事务等基础机制 | 对象由谁创建，为什么能注入依赖？ |
| Spring Boot | 简化 Spring 应用的配置、依赖组织和启动 | 项目如何从入口类启动，配置从哪里加载？ |
| Security、Redis | 在若依中参与身份、权限及登录状态处理 | 为什么 token 的校验还会访问 Redis？以源码为准 |

Maven 的多模块组织与 Controller / Service / Mapper 的职责分层是两个不同维度，不能把一个 Maven 模块简单等同于一层。若依实际业务代码分散在多个模块中。[S2]

第 3 周验收：

- [ ] 非法状态转换在后端被拒绝；不能直接通过编辑请求更改审核结果。
- [ ] 无权限用户不能审核，填报人不能访问或修改他人的私有工单。
- [ ] 无论是列表、详情还是状态变更接口，都遵守已确定的可见范围。
- [ ] 模拟记录写入失败，主表状态也回滚；能解释事务没有生效的一个实际原因。

Spring 默认代理模式下，同一对象内部调用带 @Transactional 的方法，不会因此新触发该方法的事务拦截。默认回滚规则针对 RuntimeException / Error，受检异常需结合回滚配置判断；不要背成“抛任何异常都回滚”。[S6]

## 6. JDK 8 对照规则

每天最后用约 5—10 分钟记录：本课概念在 Java 8 是否相同；如不同，差异首次出现在哪一版，Java 8 如何实现；若属于框架升级，明确写为框架差异。

| 分类 | 本月讲解方式 |
| --- | --- |
| 共同基础 | 类、接口、泛型、集合、异常、Lambda、Stream、java.time 等照常学习，不重复开两套课 |
| 8 之后的语法 / API | 遇到 var、List.of、Stream.toList、文本块、record、switch 表达式等时说明引入版本和替代写法；不将它们全部说成 Java 17 首次新增 |
| JDK 17 的使用范围 | 不启用预览特性；认识 record，但本月实体和请求对象优先沿用上传项目的普通类写法 |
| Spring 生态 | 对照 Boot 2 / 3、校验和 Servlet 相关 javax / jakarta 包名、安全配置；不把所有 javax 包都替换成 jakarta |
| 项目运行 | Spring Boot 3.5 不能通过仅修改 java.version 就在 JDK 8 上运行；旧项目以其自身依赖和编译配置为准 |

Oracle 的 Java Tutorials 明确主要针对 JDK 8；它适合基础对照。新语言特性和 API 结合 Java 17 官方资料校验，Dev.java 中超出 Java 17 的内容不纳入本月主线。[S3][S4][S5]
