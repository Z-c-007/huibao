# 手动验收清单

本文件提供你自行运行的场景，本轮未代你执行数据库或业务测试。

## 准备

1. 停止旧后端，备份自己的数据库（按需），在DBeaver管理员连接执行upgrade_v1_to_v2.sql整份脚本。
2. 启动Memurai，确认密码与APP_REDIS_PASSWORD一致。
3. IDEA运行ApprovalApplication，看到依赖检查完成；启动前端5174。
4. 使用不同浏览器或独立窗口演示不同用户；避免同一窗口切换身份时混淆数据。

## 身份与会话

- report_b正确密码登录，Network里得到三个部分的JWT；错误密码返回401。
- 个人安全页显示JWT的jti及真实Redis会话TTL，CLI查同一键能够对应。
- 退出后用原JWT请求/api/auth/me，应返回401。
- 同账号在两个设备登录，退出某一会话，另一会话仍可用。
- 更改密码后所有旧会话失效，旧密码不能登录，新密码可登录。
- 连续5次错误登录后，第6次返回429；等待锁定TTL结束再尝试。
- 停止Redis后访问认证接口应失败并提示依赖不可用，不自动放行。

## 功能权限

- report_b有填报页面，无审核、系统管理页面。直接请求审核接口也应403。
- review_b1有审核页面，无填报操作。通过修改前端DOM不能绕过后端权限。
- admin进入系统管理，将填报角色的删除权限取消；已登录report_b下一次请求失效，重新登录后删除按钮消失，直接DELETE同样403。
- 恢复权限，再分配多角色给一个新账号，验证它可以同时看到被授权的页面。
- 只有用户创建权限而没有角色分配权限，不能创建带管理角色的账号；没有角色权限管理权，不能分配系统管理权限。

## 审批闭环

1. report_b创建SF-2026-001材料，勾选review_b1、review_b2提交。
2. 在三级节点未结束前，review_a1待办中没有这份材料，猜测材料ID访问也应403。
3. review_b1通过，同节点review_b2任务关闭；二级A激活。
4. review_a1通过，集团激活；review_group通过，总体APPROVED。
5. report_c看不到report_b的材料，直接改ID访问、编辑也被拒绝。
6. 新建第二份不勾选本级审批人，直接到二级A。
7. 驳回一份材料，report_b修改重提，出现新轮次；旧审批人看旧轮快照，不看最新未分配材料。
8. 在审材料撤回，原轮次CANCELLED，当前材料DRAFT；重新提交新增一轮。
9. 升级前在审材料没有快照，应提示撤回重提；不能凭当前内容伪造历史审批材料。

## 并发、幂等与异常

- 两个窗口打开同一草稿，用同一旧版本先后保存，第二个应409。
- 两位同级审批人同时通过，只有一次成功推进，另一个409；不能跳过上一级。
- 相同requestId、版本、候选列表重试提交，返回replayed=true且只生成一轮。
- 同一个requestId换候选或版本，应409。
- 非本人材料、非候选人、未来节点、重复审批均应拒绝。
- 负金额、超长内容、缺失版本等返回400；重复项目编号返回409。
- 成功操作有project_event与审计日志；失败操作仅有失败审计，不能留下部分审批节点。
- 错误响应requestId可在backend/logs/approval.log和app_audit_log中对应。

## 账号配置变更

- admin停用review_b1，其旧会话下一次请求应401。
- admin修改某角色权限，持有者重新登录才能继续，不能使用缓存旧权限。
- 运行中审批人全部被停用时，由填报人撤回后重新分配；本轮不支持自动转办或管理员替审。
