# 阀井基础信息查询演示

目标：不写前端，通过一次 GET 请求，看到 MySQL 中的阀井数据。
本例读取全部少量教学数据，不提供增删改、筛选、分页或空间查询。

## 1. 准备数据库

在 Navicat、MySQL Workbench 或 IDEA 数据库窗口，连接本机 MySQL，选中后端
`ruoyi-admin/src/main/resources/application-druid.yml` 配置的数据库（当前为 `ry-vue`）。
打开并执行 `sql/valve_well_demo.sql`，新建教学表、插入两条示例数据。
脚本不会删除原表或覆盖已存在的同编号记录；重复执行前请确认表结构兼容。
连接账号需要有建表和插入权限；如果 ruoyi_app 没有建表权限，可用本机数据库
管理员账号导入，后端仍使用自己的配置账号读取。

项目不会自动执行这个脚本。没有导入时，请求会出现表不存在的错误。
不要重新执行若依全套初始化脚本，也不需要重新建 ry-vue 数据库。

## 2. 在 IDEA 启用本地演示接口

确认 MySQL、Redis/Memurai 正在运行，使用 JDK 17。
打开 RuoYiApplication 的运行配置：Run → Edit Configurations。
在 Program arguments（程序实参）填写：

```text
--spring.profiles.active=druid,valve-well-demo
```

如果已经有其他程序实参，保留其他参数；同一个 active 参数只填写一次。
`druid` 保留现有数据源配置，`valve-well-demo` 启用本示例 Controller。
若 IDEA 隐藏了 Program arguments，可在 Modify options 中显示该项。
重新启动 `ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`，等待“若依启动成功”。
若已有后端占用 8080，请停止旧的运行实例，再启动新实例。

此演示接口通过若依已有 @Anonymous 允许免登录，且 Controller 受 @Profile 限制，
只有显式启用 valve-well-demo 时才注册。仅用于本地学习，不要在公开服务器启用。
没有修改全局 SecurityConfig，其他接口继续使用原有认证规则。

## 3. 发一个请求

浏览器地址栏打开（默认端口为 8080）：

```text
http://localhost:8080/gis/valveWell/list
```

或者在 PowerShell 执行：

```powershell
Invoke-RestMethod 'http://localhost:8080/gis/valveWell/list' | ConvertTo-Json -Depth 5
```

浏览器直接访问即可，不需要启动 Vue，也不需要先获取 token。
如果 IDEA 支持 HTTP Client，也可打开同目录 `valve-well-demo.http`，点击 GET 左侧运行图标。
预期返回示意（wellId 由数据库实际生成，JSON 字段顺序不固定）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {"wellId": 1, "wellCode": "FJ001", "wellName": "人民路一号阀井", "location": "人民路东段", "diameter": 200, "status": "0"},
    {"wellId": 2, "wellCode": "FJ002", "wellName": "建设路二号阀井", "location": "建设路南段", "diameter": 150, "status": "1"}
  ]
}
```

diameter 单位是毫米；status 的字符串 0 表示正常，1 表示停用。
数据库没有记录时应返回 `data: []`。本例使用普通列表 data，不是分页 rows/total。

## 4. 汇报时的阅读顺序

1. `ruoyi-admin/src/main/java/com/ruoyi/web/controller/gis/ValveWellController.java`：
   根据 URL 接收请求，调用 Service，再通过继承得到的 success 包装结果。
2. `ruoyi-system/src/main/java/com/ruoyi/system/service/IValveWellService.java`：声明业务能力。
3. `ruoyi-system/src/main/java/com/ruoyi/system/service/impl/ValveWellServiceImpl.java`：
   业务实现；本例没有复杂规则，直接调用 Mapper。
4. `ruoyi-system/src/main/java/com/ruoyi/system/mapper/ValveWellMapper.java`：声明数据访问方法。
5. `ruoyi-system/src/main/resources/mapper/system/ValveWellMapper.xml`：
   namespace 关联接口，select 的 id 关联方法，SELECT 读取数据，resultMap 转换字段。
6. `ruoyi-system/src/main/java/com/ruoyi/system/domain/ValveWell.java`：
   一行记录映射为一个对象，多行组成 List；框架最终将响应转换成 JSON。
7. `sql/valve_well_demo.sql`：数据库中的表结构和教学数据。

可在 Controller、Service 的方法中设置断点，用 Debug 启动后访问 URL，观察调用顺序。
若依当前 com.ruoyi 日志级别为 debug，控制台通常也能看到 Mapper 执行 SQL 的日志。

## 5. 常见现象

- 无法连接：后端未启动、启动失败，或端口不是 8080。
- 提示未认证或找不到接口：检查启动参数，确认新 Controller 已编译并重启。
- 提示 biz_valve_well 不存在：脚本未执行，或导入到与后端不同的数据库。
- 数据库拒绝访问：核对 application-druid.yml 中的账号、密码、读表权限。
- 返回空数组：数据库表可查询，但没有数据；检查两条 INSERT 是否执行成功。

结束演示后从启动参数中移除 valve-well-demo，再重启，即可停用本演示接口。
